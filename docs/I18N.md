# Site text & translations — how it works

Languages: **EN** (source), **PT, ES, DE, FR, ZH, KO, JA**.

## Where text lives (3 places, one rule)

| Place | What | Translated by |
|---|---|---|
| `src/locales/<lang>.json` | Keyed copy used via `t("key", "English default")` | i18next |
| `src/locales/strings.json` | **English sentence → translation** for everything else (data files, plain JSX, aria-labels, form options…) | `src/lib/domTranslate.ts` (swaps text in the DOM, restores on language change) |
| `public/privacy`, `public/terms` | Legal documents | **English only on purpose** (`data-no-translate`) — have counsel produce legal translations |

You do **not** need to wrap new text in `t()`. Write plain English in a component or in `src/data/*.ts`;
if `strings.json` has that exact sentence, it is translated automatically.

## Finding a piece of text (30 seconds, not 3 hours)

```bash
npm run text -- "Map the Funnel"
```

Prints every file:line that contains the phrase, plus its row in `strings.json` and which languages it has.

## Changing existing copy

1. Change the English where `npm run text -- "<old phrase>"` shows it.
2. The old sentence no longer matches the dictionary → that text falls back to English in every language (safe, never a stale wrong translation).
3. Run the check below; it lists exactly which new sentences need translating.

## Checking everything is translated

```bash
npm run dev                 # terminal 1
npm run i18n:runtime        # terminal 2 — loads every page in every language in headless Chrome
```

Output = visible English strings still untranslated, per page/language, and a JSON list at
`scripts/.i18n-missing.json` (git-ignored). Options: `LANGS=de,ja ROUTES="/,/contact" npm run i18n:runtime`.

Other commands:

| Command | Purpose |
|---|---|
| `npm run i18n:audit` | Static scan: hardcoded JSX text, keys missing in locales, Cyrillic in values |
| `npm run i18n:dict` | Re-seed `strings.json` from the `<lang>.json` files (never overwrites existing rows) |
| `npm run i18n:dict -- merge a.json b.json` | Merge translator output `{ "<lang>": { "English": "translation" } }` |
| `npm run text -- "phrase"` | Locate text |

## Adding translations for new sentences

1. `npm run i18n:runtime` → `scripts/.i18n-missing.json`.
2. Give that list to a translator (Claude/human) → one file per language shaped
   `{ "de": { "English sentence": "Deutsch" } }`.
3. `npm run i18n:dict -- merge out_de.json out_ja.json …`
4. Re-run `npm run i18n:runtime` until it prints `✓ everything translated`.

A sentence that must stay identical in all languages (brand, code, acronym): add it with the same text as its
translation — that marks it as intentionally kept.

## Rules

- Do not translate: UPRAISER, Lenovo, Apple, Adjust, AppsFlyer, ROAS, CPA, CPI, KPI, LTV, CAC, OEM, PAI, MMP, GEOs, FinTech, client/app names.
- No Russian in the UI. Cyrillic only in code comments (`npm run i18n:audit` checks locale files).
- Text split across inline elements (`I agree to the <a>Privacy Policy</a>`) is matched per fragment — keep each fragment a complete phrase.
- Opt a subtree out of translation with the `data-no-translate` attribute.
- Text drawn on `<canvas>`/WebGL textures is not touched by the DOM layer; use `t()` there.

## Conference Hub (`/connect`) — 22 Languages

The standalone Conference Hub (`/connect`) uses its own embedded dictionary in `src/pages/conferenceHubI18n.ts`:
- **Supported (22 languages)**: EN, RU, ES, DE, FR, ZH, KO, JA, PT, AR, TR, IT, PL, UK, HE, HI, VI, TH, ID, FIL, **RO (Romanian)**, **KA (Georgian)**.
- **RTL & Script handling**: RTL for AR and HE; `HUB_PLAIN_SCRIPT` for ZH, JA, KO, HI, TH, and KA (preserves natural letter spacing).
- **Auto-detection**: Device language (`navigator.language` / `navigator.languages`) with manual language picker switch and persistence.
